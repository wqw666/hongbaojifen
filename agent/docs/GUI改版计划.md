# GUI 改版计划 v2（按使用者视角简化）

> 原则：**零技术名词、登录前只有扫码页、登录后表格化管理**。对照 5 条要求逐条落地方案，共 3 步实施。
>
> **状态：已全部实施（2026-09-04）** —— 登录门/自动环境/去 NapCat 文案 ✓；群管理·会员表格页 ✓；玩法多群勾选 + 「更多」合并 ✓。遗留小项：表格页样式未接入统一主题（沿用现有 Treeview 样式），如需进一步美化在此计划上迭代。

## 改版后的页面结构

```
登录前：单页 = 二维码 + 状态文字（「环境启动中…」「请扫码登录」）
登录后：顶栏（标题 + 连接状态 + 刷新按钮）
        Tab: 群管理 | 会员 | 游戏玩法 | 实时监控 | 更多（设置/状态/说明合并，放最后）
```

## 五条要求的落地方案

### 1. 隐藏 NapCat（零技术名词）

- 删除「启动 NapCat」按钮。**打开软件即自动检测 → 未就绪自动拉起**（后台线程检测 6099 端口，起不来才提示「环境启动失败，请重启软件」），状态文案只显示：`环境启动中… / 已就绪，请扫码 / 正在同步服务…`
- 「部署插件」不再让用户点：登录成功后**自动执行**（现有 deploy_plugin + 插件重载逻辑照用，只在失败时提示「同步服务失败，可点刷新重试」）
- 文案全局替换清单：按钮「启动 NapCat」→删除；「刷新连接」→「刷新」；所有报错提示里的 NapCat/插件 →「服务/环境」（如「服务未就绪，请稍后刷新」）
- 「使用说明」页去掉 NapCat/插件/协议等词，只留"怎么扫码、怎么加群、怎么开游戏"的操作指引

### 2. 登录门（未登录只显示扫码页）

- `MainWindow` 启动时只构建 `login_view`（二维码 + 快捷登录 + 状态行）；`main_view`（顶栏 + 5 个 Tab）**登录成功后才构建**，各 Tab 懒加载（首次切到才建）
- 后台轮询登录态：已登录 → 切主界面并自动同步服务；登录失效/掉线 → 切回扫码页
- 实现上就是两个顶层 frame 互相 grid/ungrid，不动现有各 tab 的内部逻辑

### 3. 群、会员表格化（对齐总后台风格）

新增两个 Tab（复用现成 Treeview 样式）：

- **群管理**：表格列 = 群号｜群名｜人数｜监控开关｜同步会员｜操作
  - 数据源：总后台群列表（open API `list_groups`）+ 本机监控群（watch_groups）
  - 行内操作：「开启/关闭监控」（写插件 watchGroups）、「同步会员」（调现有 run_member_sync）、「上报群信息」
  - 底部：「+ 添加群」（输群号，自动拉群名/人数/创建时间回填）
- **会员**：顶部群选择下拉 → 表格列 = QQ｜昵称｜角色｜积分｜状态
  - 数据源：插件 `/members`（群成员）+ 总后台 `query_points_batch`（积分，500/片）
  - 底部：「全部同步」按钮（该群成员批量注册为会员并拉积分，幂等，可反复点）

### 4. 不常用菜单合并放最后

- Tab 顺序：群管理 → 会员 → 游戏玩法 → 实时监控 → **更多**（放最后）
- 「更多」页内分区：① 状态（服务连接/登录账号/版本，只读一行卡）② 设置（监控参数：延迟/自抢等，折叠）③ 使用说明（滚动文字）
- 原「状态」「设置」「使用说明」3 个 tab 删除；「历史查询」并入「实时监控」页底部（一个 Tab 内上下分区：实时列表 + 历史查询导出）

### 5. 同时管理多个群

- **群管理表**：支持多选 → 批量「开启监控」「同步会员」；监控中的群行首打绿点
- **游戏玩法**：玩法选择不变；下方改为「勾选群列表」——表格列出群管理里的群，勾选即加入玩法（每行显示：当前局｜事件数｜净积分｜结算按钮），勾选/取消即时生效（引擎 `_active_groups` 已支持多群，补运行时增删群）
- 一个登录 QQ 管全部群：所有群号在「群管理」表维护一次，玩法、监控、会员同步都从这张表勾选，不用重复输入

## 约束（改版期间不变）

- 线程纪律不变（网络一律 daemon 线程 + `after(0)` 回 UI）；`integration/` 与插件协议不动
- 每步用 `打包exe.bat` 出包目测 + 真实扫码验证；改完跑 `python -m integration.smoke` 保证对接链路没被 UI 改动破坏
- 配置向后兼容：`watch_groups`/`play_group_id` 逗号串保留，新表格数据从它们读写，不另造格式
